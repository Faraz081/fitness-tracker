## Prompt

Using the Day 3 constitution for Nutrition Tracking, create a detailed,
implementation-ready Specification (Spec) for Day 3 of the MERN
fitness/workout tracking project. Day 1 (Authentication) and Day 2 (Profile +
Workouts) are complete and MUST be reused, not rebuilt. Day 3 goals: log meals/
foods with calories and macros; view daily totals (calories/protein/carbs/fat);
group entries by meal type (breakfast/lunch/dinner/snack); full Nutrition CRUD;
test complete CRUD + daily summary. Produce a precise spec covering: (1) project
structure updates (new client+server files, integration with Day 1/Day 2);
(2) data models — full Nutrition schema (owner, foodName, quantity, unit,
calories, protein, carbs, fat, mealType, date), validation + indexes, ownership;
(3) API spec — POST /api/nutrition, GET /api/nutrition (with ?date/?mealType),
GET /api/nutrition/summary/daily, GET/PATCH/DELETE /api/nutrition/:id with
request/response shapes, status codes, error cases, and owner-scoped
authorization + server-computed totals; (4) frontend spec — Nutrition page with
date selector, daily totals, grouped entries, Add/Edit MealForm, delete
confirmation, meal-type handling, loading/error states, nav updates; (5) state
management & data fetching; (6) security & authorization rules; (7) testing &
Day 3 DoD checklist; (8) out-of-scope list. Precise, unambiguous, no guessing.
