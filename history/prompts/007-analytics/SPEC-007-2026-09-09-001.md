## Prompt

/sp.specify Create a detailed functional specification for the Analytics module
of the FitTrack application based on the constitution already defined.

### Feature: Analytics (4.1)

1. Overview: A dedicated Analytics page that gives users clear, visual insights
   into their fitness progress. The page must follow the exact same UI system as
   the Dashboard (left sidebar, dark theme, green accents, tight content layout).

2. Navigation: Add "Analytics" to the left sidebar (between History and Profile
   or after Progress). When the user is on the Analytics page, the "Analytics"
   item must be highlighted as active.

3. Page Structure:
   - Top Section - Overall Fitness Summary: a summary card showing overall
     progress score or status, key highlights (e.g. "Workout consistency improved
     20% this month"), current streak, and total workouts this month.
   - Filters: time range selector (This Week | This Month | Last 3 Months |
     Custom Range); optional category filter (All, Strength, Cardio).
   - Main Analytics Sections in order:
     1. Workout Frequency - bar or line chart of workouts per day/week with
        comparison with previous period.
     2. Exercise Performance - strength volume over time (volume = sets x reps x
        weight); ability to select a specific exercise and view weight
        progression, reps progression, estimated 1RM trend.
     3. Body Weight Trend - line chart over time with optional goal weight line
        and change from start of selected period.
     4. Calories Analytics - consumed vs burned, daily/weekly average,
        surplus/deficit indication.
     5. Macronutrient Analytics - Protein/Carbs/Fat trends (stacked area or
        multi-line), average daily intake for the period.
     6. Weekly/Monthly Comparison - side-by-side comparison cards or dual charts
        with key metrics Workouts, Volume, Calories, Weight change.

4. Chart Requirements: all charts interactive (hover tooltips, zoom if
   applicable); responsive and smooth; consistent color palette (green as primary
   accent); empty states when not enough data exists (with helpful message).

5. Data Rules: only show real user data; handle sparse data gracefully;
   pre-aggregate data where possible for performance.

6. UI Rules (strict): must match Dashboard UI exactly (same left sidebar, card
   style and border radius, spacing and tight side layout, same typography and
   green accent color); content must fill the width properly (no large empty
   black areas).

7. Acceptance Criteria: Analytics page exists and is accessible from sidebar; all
   required analytics sections present; charts interactive; weekly and monthly
   comparisons work; UI visually consistent with Dashboard; empty states handled
   properly; page performs well with historical data.
