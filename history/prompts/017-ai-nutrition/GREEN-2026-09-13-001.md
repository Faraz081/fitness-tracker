## Prompt

```
/sp.implement

Implement the AI-powered Nutrition page upgrade according to the constitution, specification, plan, and tasks already defined.

### Implementation Instructions

Follow this order strictly:

1. **Audit & Foundation**
   - Inspect the current Nutrition page and preserve its existing UI, layout, black/orange theme, and structure.
   - Review the existing Nutrition model, APIs, CRUD flow, date handling, meal filters, and summary cards.
   - Identify what can be reused and what must be added for Gemini analysis and real-time updates.

2. **Secure Gemini Backend**
   - Store `GEMINI_API_KEY` only in backend environment variables.
   - Create a clean backend service/controller for AI food analysis.
   - Accept natural-language food input from the frontend.
   - Call Gemini and require structured JSON only (foodName, quantity, unit, calories, protein, carbs, fat).
   - Validate the AI response on the backend.
   - Support quantity-aware estimates when quantity is provided.
   - Handle missing API key, Gemini failure, and unidentifiable food gracefully.
   - Never expose the Gemini key to the frontend, browser, or client-side code.

3. **AI Search UX**
   - Add natural-language food search to the existing Nutrition page.
   - Add an "Analyze with AI" action.
   - Show "Analyzing food..." while processing and prevent duplicate requests.
   - Display the AI result in an editable preview before saving.
   - Allow the user to edit food name, quantity, unit, calories, protein, carbs, fat, meal type, and date.
   - Show a verification note that AI-generated values should be reviewed before saving.
   - Do not save AI results until the user explicitly confirms.

4. **Save & Meal Integration**
   - Save confirmed entries to MongoDB with the authenticated user ID.
   - Store food name, meal type, quantity, unit, calories, protein, carbs, fat, and date.
   - Support Breakfast, Lunch, Dinner, and Snack assignment.
   - Show the new entry immediately in the selected meal section.
   - Keep existing view/edit/delete functionality working with real records.

5. **Dynamic Totals & Filters**
   - Make Calories, Protein, Carbs, and Fat summary cards fully dynamic from saved entries for the selected date.
   - Make Breakfast/Lunch/Dinner/Snack filters use real database data only.
   - Recalculate totals after add, edit, delete, and date change.
   - Ensure date changes show only that day's entries and recalculate all totals.

6. **Real-Time Sync & Dashboard**
   - Refetch or invalidate Nutrition data after mutations using the existing React state/query architecture.
   - Ensure the Nutrition page updates without a manual browser refresh.
   - Ensure Dashboard nutrition values are calculated from the same Nutrition records.
   - After Nutrition add/edit/delete, Dashboard must reflect updated calories and macros.

7. **States, Cleanup & Security**
   - Add loading, AI-loading, empty, and error states.
   - Remove all static/mock nutrition data.
   - Enforce authenticated user ID filtering on all nutrition queries.
   - Verify that users cannot access each other's nutrition records.

8. **Final Verification**
   - Test Breakfast, Lunch, Dinner, and Snack AI logging flows.
   - Test edit and delete recalculation.
   - Test date filtering and recalculation.
   - Test Dashboard synchronization.
   - Test Gemini failure and invalid food handling.
   - Test multi-user data isolation.

### Rules
- Do not redesign the Nutrition page or copy an external reference website UI.
- Keep the existing black/orange theme and overall design.
- Prefer existing Nutrition models and APIs wherever possible.
- Never expose the Gemini API key on the frontend.
- Never save AI results until the user confirms.
- Never use static/mock nutrition data.
- All records and queries must be scoped to the authenticated user.
- Follow all acceptance criteria from the specification.
```
