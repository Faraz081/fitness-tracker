## Prompt

/sp.plan

Create a detailed implementation plan for the AI-Powered Nutrition Page (Day 12, constitution v4.4.0) based on the constitution and specification already defined.

### Phase 1: Audit & Foundation
1. Audit the existing Nutrition page, backend `/api/nutrition*` endpoints, Nutrition Mongoose model, and the Data flow/Dashboard aggregate.
2. Map AI integration points + confirm zero-redesign (P24) constraint cases.
3. Set up `.env.example` + optional `GEMINI_API_KEY` server env config.
4. Add optional additive `source` field (`'ai' | 'manual'`, no new models, no math change) to the Nutrition schema per constitution.

### Phase 2: Secure Gemini Backend
1. Backend-only Gemini proxy endpoint: `POST /api/nutrition/analyze`.
2. Server-side API key in env only; never exposed to the frontend.
3. Strict zod validation of the model's JSON reply (foodName, quantity, unit, calories, protein, carbs, fat) — invalid/out-of-range rejected, never surfaced raw.
4. Quantity-aware estimates when `quantity`/`unit` provided; sensible default serving otherwise.
5. Graceful errors: missing key / AI failure / unidentifiable food (retryable, no fabricated values, manual logging unaffected).

### Phase 3: AI Search UX
1. Natural-language food description input on the existing Nutrition page (no redesign).
2. "Analyze with AI" action with disabled-while-pending duplicate-request guard.
3. Show "Analyzing food..." while pending, "AI-generated nutrition values — please verify before saving." on the result.

### Phase 4: Save Flow & Meal Integration
1. Editable pre-save preview (food name, quantity, unit, calories, protein, carbs, fat, meal, date) reusing the existing MealForm.
2. Save via the existing create path (owner-scoped) with `source: 'ai'`; entry appears in the chosen meal section for the chosen date.
3. Cancel discards the preview (nothing persisted).

### Phase 5: Dynamic Totals & Filters
1. Calories/Protein/Carbs/Fat summary cards + Breakfast/Lunch/Dinner/Snack filters driven by real saved records for the selected date.
2. Date change recollects entries + totals; empty date shows mandated empty state.
3. Edit/delete recalculate totals immediately.

### Phase 6: Real-Time Sync & Dashboard Consistency
1. After any add/edit/delete, meal sections, totals, filters, and Dashboard nutrition values update without a manual refresh.
2. Dashboard and page collide on THE SAME server-computed Nutrition records — no separate dataset (P30).

### Phase 7: States / Security / Cleanup
1. Loading, analyzing, empty, invalid-food, API-failure, and config-error states (FR-022 exact strings).
2. Backend-only credential + owner-scoped isolation; no fake data anywhere.
3. Remove/detect any leftover static/mock entries.

### Phase 8: End-to-End Verification
1. `npm run build` / `node --check` clean.
2. Manual browser matrix (natural-language analyze, quantity-aware, editable preview + verification note, save → meal/totals/Dashboard, edit/delete, invalid food, missing key, Gemini failure, two-user isolation, empty date, responsive, prior-day regression) recorded in quickstart.md.

### Recommended Order / Definition of Done
Follow the phase order above; DoD = constitution Day 12 DoD-1..13.
