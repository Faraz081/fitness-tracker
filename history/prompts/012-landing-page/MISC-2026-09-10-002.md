## Prompt

User asked: "when I open my website at http://localhost:5173, it directly shows the login page, whereas it should show the landing page first, and then the user can log in whenever they want. So, please update it so that it defaults to showing the landing page instead of the login page."

## Response snapshot

- Root cause: `/` was the protected Dashboard (`ProtectedRoute`), which redirected unauthenticated visitors to `/login`.
- Added a `HomeRouter` component in `frontend/src/App.jsx` (mirrors the existing `PublicOnly` pattern): if `useAuth().loading` → null; if `user` → `<Dashboard />`; else → `<Landing />`.
- Changed the root route to `<Route path="/" element={<HomeRouter />}/>`. `/landing` stays a public route that always shows the Landing page.
- Logged-in users still land on the Dashboard at `/` (intended); guests now land on the Landing page. Primary CTAs keep clean handoff (authed clicks on /register//login redirect to the app).
- Updated `quickstart.md` Gate 3 to document home routing. Verified build + live dev transform.

## Outcome

- ✅ Impact: http://localhost:5173 now defaults to showing the Landing page for logged-out visitors; authenticated users get the Dashboard. `Login`/`Register` untouched.
- 🧠 Reflection: The user is logged in in their normal browser, so they will STILL see the Dashboard at `/` in that session — noted to them that `/landing` always shows the Landing page, or log out/incognito to preview the guest path at `/`.
