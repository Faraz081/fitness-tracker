## Prompt

Using the Day 3.1 constitution for Activities & Workout History, create a
detailed Specification (Spec).

Project continues from Day 1.1 (Dashboard) and Day 2.1 (Progress & Goals). Both
are already complete and must be fully reused.

Constraints:
- Use only .js and .jsx files (no TypeScript)
- Keep the same modern dark theme from previous days
- Clean, production-ready, non-over-engineered React code

Focus strictly on these Day 3.1 goals:
- Complete workout history
- Workout detail view
- Exercise history
- Sets / reps / weight history
- Workout categories
- Workout filters
- Date-based filtering
- Personal records / best performance
- Better workout cards

Produce a complete, implementation-ready Specification that includes:

1. **Project Structure Updates** - New files and folders to be added; how they
   integrate with the existing Sidebar + Navbar layout
2. **Data Shapes** - Workout structure; Exercise structure (including sets,
   reps, weight, notes); Category structure; Personal records structure; example
   data for empty and filled states
3. **Component Breakdown** - every component required + responsibility of each
4. **Workout History Page Layout** - exact sections and order; how workout cards
   are displayed; how filters (category + date) work; how personal records are
   shown
5. **Workout Detail View** - what information must be shown; how sets/reps/weight
   history is displayed; navigation behavior (back to history)
6. **Filtering System** - category filters; date-based filtering rules; combined
   filter behavior
7. **Personal Records / Best Performance** - how calculated; how displayed
8. **Improved Workout Cards** - design and content rules; what each card must show
9. **State Management** - what data stored in state; simple and clean approach
10. **UI & Design Rules** - consistency with previous dark theme; empty states for
    all sections; responsive behavior
11. **Definition of Done** - clear checklist confirming Day 3.1 is complete
12. **Out of Scope** - explicitly list what must NOT be built (backend, real API,
    authentication, etc.)

Make the specification precise, unambiguous, and ready for implementation
without guessing.
