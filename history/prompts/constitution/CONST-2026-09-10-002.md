## 8.1 — Reports & Export

### Purpose
Define the complete specification for the Reports & Export module. This module
must allow users to view comprehensive fitness, workout, nutrition, and progress
reports, filter them by date range, and export the data in both CSV and PDF
formats. All reports must be accurate, performant, and consistent with the rest
of the application's data model and design system.

### Scope
- Fitness Report page (overview dashboard)
- Workout Report
- Nutrition Report
- Progress Report
- Date-range selection (with presets + custom range)
- Export to CSV
- Export to PDF
- Download / Generate Report action buttons
- Loading, empty, and error states for all report views and export actions

### Functional Requirements

1. **Fitness Report Page (Overview)**
   - Display a summary dashboard combining key metrics from Workout, Nutrition,
     and Progress.
   - Show high-level cards/KPIs: Total Workouts, Total Volume, Calories Consumed
     vs. Goal, Weight Change, Consistency Score, etc.
   - Allow quick navigation or tabs to the detailed Workout, Nutrition, and
     Progress reports.
   - Support the same date-range filter as the detailed reports.

2. **Workout Report**
   - List of workouts within the selected date range (date, name/type, duration,
     volume, sets, reps, personal records).
   - Aggregated metrics: total workouts, total volume, average duration, most
     trained muscle groups, PR count.
   - Visualizations (charts): volume over time, workout frequency, muscle group
     distribution.
   - Ability to drill down into individual workout details.

3. **Nutrition Report**
   - Daily or weekly nutrition summaries (calories, macros: protein, carbs, fat).
   - Comparison against user goals (if goals exist).
   - Charts: calorie intake over time, macro distribution, goal adherence.
   - List of logged meals/foods if applicable, or daily totals.

4. **Progress Report**
   - Body measurements / weight tracking over time.
   - Strength progress (key lifts or custom tracked exercises).
   - Visual progress (photos if the feature exists, or progress photos timeline).
   - Charts: weight trend, strength progression, body composition if available.
   - Highlight personal records and milestones.

5. **Date-Range Selection**
   - Required on every report page.
   - Presets: Last 7 days, Last 30 days, Last 90 days, This Month, Last Month,
     This Year, All Time.
   - Custom range picker (start date + end date).
   - Default to Last 30 days.
   - Changing the range must re-fetch / re-calculate all metrics and charts on
     the current report.
   - Persist the selected range across report tabs if possible (or at least
     within the session).

6. **Export Functionality**
   - **Export CSV**: Generate a downloadable CSV containing the raw or summarized
     data of the currently viewed report (respecting the selected date range).
   - **Export PDF**: Generate a well-formatted PDF report that includes:
     - Report title and date range
     - Key metrics / summary cards
     - Relevant tables
     - Charts (as static images)
     - Branding / app logo and generation timestamp
   - Both export actions must be available on Fitness, Workout, Nutrition, and
     Progress reports.
   - Buttons should clearly indicate "Export CSV" and "Export PDF" (or a single
     "Export" dropdown with both options).
   - Show loading state while the file is being generated.
   - Handle large date ranges gracefully (timeouts, pagination of data if needed,
     or clear messaging).

7. **UI / UX Requirements**
   - Consistent layout and component usage across all report pages.
   - Clear primary action buttons for export.
   - Responsive design (desktop + mobile).
   - Empty states when no data exists for the selected range.
   - Skeleton loaders or progressive loading for charts and tables.
   - Error states with retry option for failed data fetches or export generation.

### Non-Functional Requirements
- Reports must load quickly (target < 2s for typical 30-day ranges).
- Exports must complete within a reasonable time (target < 10s for normal
  ranges).
- All calculations (volume, totals, averages, progress deltas) must be accurate
  and match the underlying workout/nutrition/progress data.
- PDF exports should be print-ready and look professional.
- Accessibility: proper labels, keyboard navigation, sufficient contrast.

### Data & Integration Notes
- All reports must pull from the same source of truth as the rest of the
  application (workouts, nutrition logs, body metrics, goals).
- Respect user privacy and only show data belonging to the authenticated user.
- Date ranges must be handled in the user's local timezone or consistently
  documented.

### Acceptance Criteria
- [ ] User can open the Fitness Report page and see an overview of key metrics
      for the selected date range.
- [ ] User can switch between Workout, Nutrition, and Progress detailed reports.
- [ ] Date-range selector works with both presets and custom ranges and updates
      all data accordingly.
- [ ] User can export the current report as CSV and successfully download a valid
      CSV file.
- [ ] User can export the current report as PDF and successfully download a
      well-formatted PDF.
- [ ] Empty, loading, and error states are handled gracefully.
- [ ] Charts and tables accurately reflect the data for the chosen period.
- [ ] Mobile and desktop experiences are polished and usable.

### Out of Scope (for this constitution section)
- Emailing reports
- Scheduling recurring reports
- Sharing reports with coaches/trainers
- Advanced filtering beyond date range (unless already present in the app)
- Custom report builder

Please generate a complete, precise, and implementation-ready constitution
specification for section 8.1 — Reports & Export based on the above
requirements.
