## Prompt

Create a Spec-Driven Development (SDD) constitution for Day 3.1 of the Fitness
Tracker project.

Project continues from Day 1.1 (Dashboard) and Day 2.1 (Progress & Goals). Both
are already complete and must be fully reused.

Day 3.1 Goal: Build the Activities & Workout History section using only .js and
.jsx files (no TypeScript).

Features that must be fully specified: Complete workout history; Workout detail
view; Exercise history; Sets / reps / weight history; Workout categories;
Workout filters; Date-based filtering; Personal records / best performance;
Better workout cards.

Design & Technical Rules: keep the same modern dark theme from previous days
(deep black/charcoal, clean cards, consistent typography); use only .js and .jsx
files (strictly no TypeScript); clean, generic, production-ready React code; no
AI-looking comments or over-engineering; fully responsive; match the overall
visual language of the existing dashboard; reuse existing layout (Sidebar +
Navbar) where possible.

Constitution Requirements: 1) clear extension of the existing project structure
(do not break Day 1.1 or Day 2.1); 2) component breakdown for Activities &
Workout History; 3) data shape decisions (workout, exercise with sets/reps/
weight, category, personal records); 4) Workout History page layout and behavior;
5) Workout Detail view rules; 6) filtering system (category + date-based);
7) Personal Records / Best Performance logic; 8) Improved Workout Card design
rules; 9) empty states for all sections; 10) state management approach (simple
and clean); 11) coding standards (naming, file organization, simplicity);
12) success criteria / Definition of Done for Day 3.1; 13) what is out of scope
for Day 3.1 (backend, real API, authentication, etc.).

Output a complete, clear, and strict constitution document that a coding agent
or developer can follow exactly to build the Activities & Workout History
feature.
