## Prompt

/sp.constitution

You are defining the constitutional rules and non-negotiable principles for the
Reports & Export system of the FitTrack application.

### 1. Purpose
This constitution governs how users generate, view, and export fitness reports.
Reports must be clear, accurate, and useful for reviewing progress. Export
functionality must be reliable and produce clean, well-structured files.

### 2. Core Principles

- **Accuracy First**: Every report must reflect real user data. Never invent or
  approximate missing values.
- **Clarity**: Reports should be easy to understand at a glance, with clear
  sections, summaries, and visual hierarchy.
- **Consistency**: The Reports page and all report views must follow the exact
  same design system as the Dashboard (left sidebar, dark theme, green accents,
  tight content layout with minimal side gaps).
- **User Control**: Users must be able to select a date range and choose what to
  export.
- **Reliability**: CSV and PDF exports must be correctly formatted and
  downloadable without errors.
- **Performance**: Generating reports and exports should remain fast even with
  larger historical datasets.

### 3. Required Capabilities (Non-Negotiable)

The system must support:

- Dedicated Fitness Report page
- Workout report
- Nutrition report
- Progress report
- Date-range selection
- Export to CSV
- Export to PDF
- Clear Download / Generate Report buttons

### 4. Technical Constraints

- All reports must respect the selected date range
- CSV exports must be properly structured and readable in spreadsheet software
- PDF exports must be clean, well-formatted, and suitable for sharing or printing
- Handle empty or sparse data gracefully (show clear messages instead of broken
  reports)
- Prefer pre-aggregated data where possible for better performance

### 5. Design & UX Rules

- Reports page must use the same left sidebar navigation and overall layout as
  the Dashboard
- Content must have tight side spacing (no large empty black areas)
- Date-range selector and action buttons must be clearly visible and consistent
  with the existing design system
- Report sections should be organized in clean cards or sections
- Empty states must be helpful and guide the user

### 6. Out of Scope

- Scheduled / automatic email reports
- Sharing reports via social media or public links
- Advanced custom report builders
- Excel (.xlsx) export (CSV + PDF is sufficient for now)
- Watermarking or branded PDF templates beyond basic clean formatting

### 7. Success Criteria

The Reports & Export system is considered complete when:
- Users can view Workout, Nutrition, and Progress reports for a selected date
  range
- Users can export reports as CSV and PDF
- Date-range selection works correctly
- The UI is fully consistent with the rest of the application
- Exports are accurate and usable
