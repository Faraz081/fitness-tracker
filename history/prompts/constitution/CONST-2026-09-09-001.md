## Prompt

You are defining the constitutional rules and non-negotiable principles for the
Analytics module of a modern fitness tracking application (FitTrack).

### 1. Purpose
This constitution governs the design, architecture, data handling, and user
experience of the dedicated Analytics page and all related analytics features.
Every implementation decision must strictly adhere to these principles.

### 2. Core Principles
- **Data-Driven Clarity**: Every chart, metric, and summary must provide clear,
  actionable insight. No vanity metrics. Prefer trends, comparisons, and progress
  over raw numbers.
- **Consistency with Existing UI**: The Analytics page must follow the exact same
  design system as the Dashboard (left sidebar navigation, dark theme, green
  accent color, card styles, spacing, and tight content layout with minimal side
  gaps).
- **Performance First**: All analytics must load fast. Heavy calculations should
  be pre-computed or cached. Charts must remain smooth even with large historical
  datasets.
- **Privacy & Accuracy**: Only use user-owned data. Never invent or approximate
  missing data. Clearly indicate when data is insufficient.
- **Progressive Disclosure**: Show high-level summaries first. Allow users to
  drill down into detailed charts (volume, reps, weight, macros) without
  overwhelming the initial view.

### 3. Required Capabilities (Non-Negotiable)
The Analytics page must include:
- Dedicated Analytics page accessible from the main navigation
- Workout frequency analytics (daily/weekly/monthly frequency)
- Exercise performance analytics (strength progression, volume, estimated 1RM
  trends)
- Weight trend analytics (body weight over time with optional goal line)
- Calories analytics (consumed vs burned, deficit/surplus trends)
- Macronutrient analytics (Protein / Carbs / Fat breakdown and trends)
- Weekly and monthly comparison views
- Interactive charts (hover, zoom, filter by date range)
- Overall fitness summary card (key insights + progress score)

Detailed charts required:
- Strength volume over time
- Reps and weight progression per exercise
- Nutrition trends (calories + macros)

### 4. Technical Constraints
- All charts must be interactive and responsive
- Support weekly and monthly time ranges by default, with custom date range
  option
- Data must be aggregated efficiently (no N+1 queries)
- Empty states must be helpful and guide the user to log more data
- The page must remain usable even with sparse data

### 5. Design & UX Rules
- Left sidebar navigation must remain consistent (Dashboard, Workouts, Nutrition,
  Progress, Goals, History, Analytics, Profile)
- Content must fill the available width with minimal side padding (same tight
  layout as Dashboard)
- Use the same card style, border radius, typography, and green accent color
- Charts should use a clean, modern style that matches the rest of the app
- Mobile responsiveness is required

### 6. Out of Scope
- Social sharing of analytics
- Comparison with other users
- AI-generated coaching advice (unless separately specified)
- Export to PDF/CSV (can be added later)

### 7. Success Criteria
The Analytics page is considered complete when:
- All listed analytics types are present and functional
- Charts are interactive and performant
- UI is visually indistinguishable in style from the Dashboard
- Users can clearly understand their progress at a glance and drill deeper when
  needed
