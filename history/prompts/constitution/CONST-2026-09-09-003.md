## Summary

Updated `.specify/memory/constitution.md` from **v3.4.0 → v3.5.0** (MINOR)
to add the Day 6.1 Notifications & Reminders frontend phase. This follows the
established pattern of frontend-only phases (Day 1.1, 2.1, 3.1, 4.1, 5.1) that
extend the JS-only override and add domain-specific principles + rules. It
introduces ONE deliberate, narrow exception to the prior no-persistence rule:
read/unread state + notification settings persist to a single localStorage key
(N9) per the feature requirements; filter/search state remains non-persistent
(S5 intact).

### New Section: Day 6.1 — Notifications & Reminders
- **Goal**: dedicated Notifications page, toasts, sidebar unread badge, and
  per-type Settings; all client-side, derived from workout/goal/nutrition data
- **Core Principles**: N1-N10 (relevance first, user control, design
  consistency, clarity, respect attention, reliability/timeliness,
  deduplication, graceful absence handling, narrow client-side persistence,
  additive navigation)
- **Notification Type Rules**: six types — workout completion, goal progress,
  completed goal, workout reminder, meal reminder (meal windows +
  `GOAL_REMINDER_DAYS` in `data/constants.js`), goal reminder
- **Data & Dedup Rules**: mock descriptors + EMPTY variant; `eventKey` =
  `${type}:${entityId}:${YYYY-MM-DD}`; pure generators in
  `utils/notificationsUtils.js` with `generateNotifications` entry point
- **Settings Rules**: per-type on/off, persist to `notificationsState`
  localStorage key (N9), apply instantly; quiet hours out of scope
- **Notifications Page Rules**: `/notifications` in DashboardLayout, unread
  grouping, mark all read, dismiss, clear all, nav badge, designed empty states
- **State Management**: local useState + existing useLocalStorage hook pattern;
  ONE NotificationsContext in `context/` if cross-component state needed
- **Folder & Component Structure**: components/notifications/ (`NotificationList`,
  `NotificationItem`, `NotificationSettings`, `EmptyNotifications`,
  `NotificationToast`), pages/Notifications.jsx, data/notificationsData.js +
  constants additions, utils/notificationsUtils.js
- **UI/UX Rules**: same dark tokens/accent, unread = accent-tinted border + dot +
  bold title (never color-only), toast behavior, badge pill, a11y
- **Coding Standards**: .js/.jsx only, pure deterministic generators, zero new
  npm dependencies, no backend/API/env/model changes
- **Definition of Done**: 12 criteria covering the six types, settings,
  read/unread, persistence, dedup, empty/edge states, design, build, manual
  verification, accessibility
- **Out of Scope**: 15 deferred items (push/email/SMS, backend notification
  models, social, AI text, complex quiet hours, per-entity rules, cross-device
  sync, websockets, etc.)
