## Prompt

/sp.constitution

Constitutional rules and non-negotiable principles for the Settings system of
the FitTrack application. Purpose: give users clear control over their account,
preferences, and data while remaining simple, secure, and consistent with the
rest of the product.

Core principles required: User Control, Clarity & Safety (destructive actions,
especially Delete Account, clearly labeled + confirmation), Consistency (same
design system as Dashboard), Security First (password change + deletion secure),
Immediate Feedback, Minimal Friction.

Non-negotiable capabilities: account settings; notification preferences; units
(kg/lb); theme; profile preferences; change password; logout; delete account
(with confirmation).

Technical constraints: preferences (units, theme, notifications) persisted;
password change requires current password + validation; delete account is a
deliberate confirmed act (never single click); logout clears session cleanly;
settings load current preferences correctly.

Design/UX: same left sidebar + Dashboard layout; tight side spacing; group
related settings (Account, Preferences, Notifications, Danger Zone); destructive
actions visually distinct + confirmation; inputs/toggles/buttons match the
design system.

Out of scope: 2FA; connected social accounts; advanced privacy controls; export
all data; theme options beyond the supported ones.

Success criteria: update profile/units/theme/notification prefs; change password
securely; log out cleanly; delete account only after clear confirmation; whole
experience consistent with the app.
