## Prompt

/sp.constitution

You are defining the constitutional rules for the Final Testing & Requirements Check of the FitTrack application.

### 1. Purpose
This constitution governs the final QA and verification phase that validates every feature built across all prior days against the original requirements. It is NOT a new feature build — it is a structured, evidence-based audit.

### 2. Core Principles

- **Requirements Traceability**: Every requirement from every spec must be individually verified with a pass/fail result and evidence.
- **End-to-End Coverage**: Every user-facing flow must be tested end-to-end from the browser against a live server.
- **No Silent Failures**: Every error path, empty state, loading state, and edge case must be explicitly tested and confirmed correct.
- **Cross-Device Quality**: Every page must be verified at desktop, tablet, and mobile breakpoints.
- **Fix Before Finish**: No feature may be signed off with known unfixed bugs that affect usability.
- **Evidence-Based Sign-off**: Final sign-off must be backed by written records of every test performed.

### 3. Required Testing Areas (Non-Negotiable)

- CRUD operations (workouts, nutrition, profile)
- Authentication flow (signup, login, logout, session, protected routes)
- Dashboard calculations & metrics
- Charts & analytics
- Search & filtering
- Notifications & reminders
- Settings (preferences, units, theme, password, account deletion)
- Reports & export (CSV + PDF)
- Mobile & tablet responsiveness

### 4. Constraints

- No new features, pages, components, or API endpoints
- No major visual redesigns beyond fixing broken layouts
- No automated test suite creation
- No infrastructure or deployment changes
- No backend architecture changes

### 5. Process Rules

- One feature at a time — complete before moving on
- Record results immediately — not from memory at end of day
- Fix, then re-test — confirm the fix before moving on
- Regression after fix — re-test surrounding area
- No sign-off under uncertainty — ambiguity is a FAIL

### 6. Success Criteria

- Every testing area has at least one documented PASS result
- Every requirement from every spec individually verified
- All bugs found during Day 9 fixed and re-tested
- No console errors, uncaught exceptions, or stack traces
- Written test report exists with evidence
- `npm run build` succeeds cleanly after all fixes
- `node --check` passes for backend after all fixes
