## Prompt

/sp.constitution

You are defining the constitutional rules and non-negotiable principles for
rebuilding the Nutrition page in the FitTrack application as a clean, minimal
"AI Food Search" page. The current Nutrition page is declared BROKEN and
OVERCOMPLICATED and is being REBUILT FROM SCRATCH. Everything it does MUST be
removed first, then reconstructed ONLY to the exact structure you specify.

### 1. Purpose

Delete the existing Nutrition page implementation completely (page,
components, state, files created specifically for it), then rebuild the page
to exactly five parts: a Header, a Search Bar, a Search Result, Meal Tabs,
and a Meal Section. Nothing more, nothing less.

### 2. Core Principles (Non-Negotiable)

- **Delete First**: The old Nutrition page MUST be completely deleted BEFORE
  any new build. No patching or partial reuse.
- **Exact Structure Only**: The page MUST contain exactly the five parts
  specified below — no additions, no omissions.
- **Minimal by Design**: Simplicity over feature richness; every part does
  exactly ONE thing.
- **Live AI Only**: Every search MUST call the Gemini API in real time through
  the backend. No static nutrition database, dummy JSON, or hardcoded values
  as the source of truth.
- **Real Persistence**: Added foods MUST save to the real backend/database and
  appear under the selected meal immediately. No local-only fake persistence.
- **No Scope Creep**: No feature beyond the specified structure may be added.
- **Secure AI Integration**: The Gemini key MUST remain backend-only and never
  be exposed to the frontend.

### 3. Required Structure (Non-Negotiable, Exact)

The page MUST be rebuilt to exactly these five parts:

1. **Header** — a fork/utensil icon and the title "AI Food Search".
2. **Search Bar** — ONE search input, a "Search" button, and the helper text:
   "Supports natural language — try 'large chicken breast' or '100g of oats
   with milk'".
3. **Search Result** — a label "1 RESULT — CLICK TO ADD", a "Clear" link, and
   a result row showing: the food name, the serving size (e.g. "per 118g"),
   four badges — CAL, P, C, F — in distinct colors, and a "+" icon. The data
   MUST come from a live Gemini call. Clicking the row or "+" adds the food.
4. **Meal Tabs** — Breakfast, Lunch, Dinner, Snacks, each with its own icon
   (coffee cup, sun, moon, clock).
5. **Meal Section** — the active meal's foods. Empty state: a plate/utensils
   icon + "No food logged for [Meal Name]" + the hint "Use AI search above to
   find and add foods." With foods: the persisted entries showing macros.

### 4. Technical Constraints

- JavaScript only (no TypeScript per the Day 6.1 override).
- Zero new frontend and zero new backend dependencies.
- Reuse the existing auth-scoped `POST /api/nutrition/analyze` Gemini proxy
  and the existing owner-scoped Nutrition create path (additive `source: 'ai'`
  marker).
- The Gemini API key MUST stay backend-only (optional env var; app keeps
  working without it, AI path fails gracefully).
- Handle Gemini failure and unrecognized food gracefully; never fabricate
  values or write data on failure.

### 5. UX Rules

- Keep the flow one focused line: search -> one live result -> add to active
  meal -> persisted row in the Meal Section. No extra screens.
- CAL / P / C / F badges in four distinct colors; lucide-react icons; real
  input/button elements.

### 6. Out of Scope (Forbidden on this page)

- Date picker; separate macro summary bar; extra filters; duplicate search
  bars; sidebar widgets specific to this page.
- An add-to-log modal or quantity editing (the "+" adds directly).
- Fiber / Sugar / Sodium display rows.
- Photo/barcode logging, favorites, meal templates, curated food DB.
- Any feature not in the specified structure.

### 7. Success Criteria

The rebuild is complete only when:
1. The old Nutrition implementation is fully deleted before the new build.
2. The page matches the exact five-part structure.
3. Every search returns live Gemini data (no static source of truth).
4. Adding saves to the real backend and appears immediately under the meal.
5. Empty meal sections show the specified empty state.
6. Saved foods display their macros.
7. No unlisted extra features exist on the page.
8. The Gemini key appears in zero client-facing surfaces and zero committed
   files; second-user isolation holds.
9. Build/checks pass and manual browser verification is recorded.

### 8. Process Rules

- First: confirm the complete deletion of the old Nutrition page, its
  components, and related state/files BEFORE any new build.
- Then: rebuild exactly and only to the structure above.
- Stop immediately if tempted to add any unlisted feature.
