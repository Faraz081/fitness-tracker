## Prompt

/sp.constitution

New feature: **Public Landing Page** for the FitTrack application (the Fitness
Tracker).

### Purpose
The landing page is the conversion-focused public face of the product. It must
convince visitors — who are NOT yet registered — to sign up, while looking
like an extension of the authenticated app's design system (dark theme + green
accent). It is a single, content-driven page with sections that lead the
visitor from attention → interest → desire → action (sign-up).

### Required Sections (all must be present, conversion-ordered)
1. Public landing page (no login required)
2. Navbar — logo/brand, on-page anchors, primary CTA
3. Hero — headline + supporting copy + primary/secondary CTA buttons + an
   ANIMATED hero element
4. Features — product capabilities presented as benefits
5. How It Works — simple numbered steps
6. Fitness Statistics — compelling, honest figures the app really produces
7. Benefits — "why FitTrack" outcomes
8. Testimonials — authentic/clearly illustrative, not fabricated-as-real
9. Final CTA — closing headline + sign-up CTA
10. Footer — brand, links, Login / Sign up

### Design Rules
- Visual hierarchy: one clear primary CTA per viewport; headline → value →
  CTA.
- Brand colors: dark theme + `--color-accent` lime (`#A3E635`); token-based
  gradients/glows, no new color system.
- Modern buttons (accent filled + outline/ghost secondary), consistent 4px
  spacing scale, premium, not template-like.
- Authentic testimonials — placeholder/illustrative content marked as such,
  swap-able from one content source.
- Footer links are real or absent — no dead placeholders.

### Technical Constraints
- Fully responsive (mobile-first, no horizontal scroll at any breakpoint).
- Smooth, lightweight animations (CSS/SVG transforms + opacity; reuse the
  already-bundled framer-motion; no heavy 3D/video).
- Every CTA leads to the correct auth/sign-up flow (primary → sign-up/
  register, secondary → login).
- Content is easy to update — ALL copy, stats, testimonials, nav links, and
  CTA targets live in a single content module (`data/landingContent.js`);
  editing content must not require component changes.
- JavaScript-only (`.js`/`.jsx`), zero new npm dependencies, zero new env
  vars, no backend/API/model changes.
- Public page: accessible (semantic landmarks, single `h1`, labelled links,
  alt text, focus-visible, contrast on dark) + basic SEO (descriptive title,
  meta description).

### Out of Scope
- Blog / content-marketing sections.
- Pricing tables / plans page.
- Live chat widgets.
- Complex 3D/WebGL or hero video backgrounds.
- Multi-language (i18n).

### Success Criteria
- Landing page renders publicly without login; existing routes untouched.
- All required sections present and coherent.
- All CTAs route to the correct auth flow; zero dead links.
- Visually consistent with the authenticated app (dark + lime).
- Fully responsive mobile-first; no horizontal scroll.
- Animations smooth and disabled under prefers-reduced-motion.
- Fast first load (LCP budget recorded); no bundle bloat; zero new deps.
- Content updates require zero component changes.
- `npm run build` (vite build) succeeds cleanly.

Generate the complete constitution amendment (principles + domain rules +
Definition of Done + Out of Scope) for this feature and append it to
`.specify/memory/constitution.md` as the governing constitutional context.
