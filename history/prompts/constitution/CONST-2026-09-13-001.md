## Prompt

/sp.constitution

You are defining the constitutional rules and non-negotiable principles for
building the Nutrition Search feature in the FitTrack application.

### 1. Purpose
This constitution governs the creation of a real-time AI-powered food search
experience. Users must be able to type only a food name in natural language,
receive live nutrition data from Gemini, review a result card, adjust quantity
in a modal, and save the food into the correct meal section in the real
database.

### 2. Core Principles

- **Live AI Only**: Every search must call the Gemini API in real time. No
  static nutrition database, dummy JSON, cached permanent food catalog, or
  hardcoded nutrition values are allowed as the source of truth.
- **Natural Language Input Only**: The user types only the food name/
  description. They must not be forced to manually enter calories, protein,
  carbs, or fat to start the search.
- **Editable Before Save**: AI results are estimates. The user must be able to
  adjust quantity before saving, and nutrition values must recalculate
  dynamically from the real AI data.
- **Real Persistence**: Saving a food must write to the actual backend/database
  so the entry persists and appears under the correct meal section on the main
  nutrition log.
- **Immediate Reflection**: After saving, the main log must update in real time
  under the selected meal. No local-only or session-only fake persistence.
- **Honest Empty States**: If a meal has no logged food, show a clear empty
  state instead of placeholder entries.
- **Secure AI Integration**: The Gemini API key must remain backend-only and
  must never be exposed to the frontend.
- **User Isolation**: All saved nutrition logs must be scoped to the
  authenticated user.

### 3. Required Capabilities (Non-Negotiable)

The feature must support:

- Single search bar for natural-language food names
- Real-time Gemini nutrition lookup on search
- Result card with:
  - Food name + "AI" badge
  - Per standard serving nutrition: Calories, Protein, Carbs, Fat
  - Second row: Fiber, Sugar, Sodium
- "+" action on the result card that opens an Add-to-Log modal
- Add-to-Log modal with:
  - Food name + AI badge
  - Close (X)
  - Nutrition breakdown
  - Editable Quantity (g)
  - Live recalculation for the entered quantity
  - "Add To" dropdown: Breakfast / Lunch / Dinner / Snacks
  - Cancel and + Add Food actions
- Database persistence of the saved food log
- Real-time appearance under the correct meal section
- Empty state: "No food logged for [Meal]" with hint to use AI search

### 4. Technical Constraints

- Every search must hit Gemini live
- Nutrition calculations for changed quantity must be derived from the real API
  result, not hardcoded ratios disconnected from the response
- Saved entries must include authenticated user ID, meal type, quantity, and
  nutrition values
- Prefer existing Nutrition model/APIs where possible
- Handle Gemini failure and unrecognized food gracefully
- Do not pre-fill the page with fake foods or permanent placeholder nutrition
  data

### 5. UX Rules

- Keep the flow simple: search → result card → modal → save
- Quantity changes must immediately update the displayed "For [X]g: [Y] kcal |
  P | C | F"
- Empty meal sections must be explicit and helpful
- Do not make the UI depend on static demo content

### 6. Out of Scope

- Building a local offline nutrition database as the primary source
- Requiring manual macro entry just to search
- Session-only food logs that disappear on refresh
- Exposing Gemini credentials to the client
- Redesigning unrelated parts of the application

### 7. Success Criteria

The Nutrition Search feature is considered complete when:
- Users can search food names in natural language
- Every search fetches live Gemini nutrition data
- Result cards and modal show dynamic AI-based values
- Quantity changes recalculate nutrition live from the AI data
- Saving persists the food to the backend/database
- The food appears under the correct meal section in real time
- Empty meal states are shown correctly
- No static/hardcoded nutrition source remains as the source of truth
- All saved data is scoped to the authenticated user
