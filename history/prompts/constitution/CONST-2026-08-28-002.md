## Prompt

Amend the SDD constitution for Day 3 of the MERN fitness/workout tracker
(Fitness_Tracker) — Nutrition Tracking. Day 1 auth and Day 2 profile/workouts are
complete on prior branches and MUST be reused unchanged. Day 3 must be fully
specified: log meals/foods with calories and macros, view daily totals
(calories/protein/carbs/fat), group entries by meal type (breakfast/lunch/dinner/
snack), full Nutrition CRUD, and a server-computed daily summary. Requirements:
extend structure without breaking auth; keep the same stack, no new deps or env
vars; Nutrition data model (owner-scoped, single doc per food/meal); API
contracts for full nutrition CRUD + daily summary; frontend Nutrition page
(date selector, daily totals, grouped entries, add/edit/delete with confirm);
ownership authorization (Principle VII extended to nutrition); server-computed
totals (new Principle VIII); Day 3 Definition of Done; later-day deferrals; keep
Day 1 + Day 2 sections intact. Output a complete amended constitution to
.specify/memory/constitution.md, then create a PHR (stage: constitution).

## Response snapshot

Amended the constitution from v2.1.0 -> v2.2.0 (MINOR: new business domain +
added Core Principle VIII). Preserved all Day 1 and Day 2 principles/sections;
restated that Day 3 adds NO new required env vars. Extended Principle VII
"Resource Ownership & Authorization (NON-NEGOTIABLE)" to cover nutrition entries
(owner set from req.userId only; every query owner-scoped; 404 for not-owned).
Added Principle VIII "Calorie & Macro Totals Are Server-Computed
(NON-NEGOTIABLE)" requiring the daily total calories/protein/carbs/fat to be
aggregated server-side across only the caller's own entries, with the client

protein, carbs, fat, mealType, date, timestamps, {owner,date,mealType} index);
