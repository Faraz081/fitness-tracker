## Prompt

Create a Spec-Driven Development (SDD) constitution for Day 1.1 of a Fitness
Tracker project. Day 1.1 Goal: build a modern dark-themed Fitness Tracker
dashboard in React using only .js and .jsx files (strictly no TypeScript),
matching a reference screenshot as closely as possible. REQUIRED: exact layout
(fixed left sidebar with logo + Dashboard/Exercise/Nutrition + profile block at
bottom; top navbar with logo + "Fitness Tracker", center tabs Dashboard/
Workouts/Nutrition/Goals/BMI, user avatar + name; main area with QUICK LOG
buttons Water/Steps/Calories/Sleep/Weight/Workout). Required dashboard content:
personalized greeting + current date; summary cards (Total Workouts, Total
Exercises, Calories Burned, Calories Consumed, Current Weight, Workout Streak);
daily goal/progress cards (Hydration, Calories, Steps, Sleep) with progress
bars; activity/progress rings; weekly workout chart; calories chart; macro
chart; recent workouts; quick action buttons; proper empty states everywhere.
Design rules: dark modern UI (deep black/charcoal backgrounds, subtle card
elevation, clean typography), match screenshot, .js/.jsx only, no AI-looking
comments, no over-engineering, fully responsive, reusable components, proper
empty states. Constitution MUST include: project structure/folder organization;
component breakdown (Sidebar, Navbar, SummaryCards, ProgressCards, Charts,
RecentWorkouts, etc.); design-system decisions (colors, spacing, typography,
card style); state management approach (local React state or Context); how empty
states look/behave; responsive behaviour rules; coding standards (naming, file
structure, no unnecessary complexity); Definition of Done for Day 1.1; what is
out of scope for Day 1.1 (backend, real API, authentication, etc.). Output a
complete, clear, strict constitution a coding agent can follow exactly, written
to .specify/memory/constitution.md, then create a PHR (stage: constitution).
