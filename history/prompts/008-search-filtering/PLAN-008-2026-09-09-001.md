## Prompt

Via /sp.plan using the Day 5.1 constitution (.specify/memory/constitution.md,
v3.4.0) and the Search & Filtering Specification
(specs/008-search-filtering/spec.md), create a detailed Implementation Plan for
client-side search + multi-dimension filtering (date range, category, meal
type) across the Workouts (/workouts), Exercises (/exercises), and Nutrition
(/nutrition) pages, plus Workout History (/workouts-history) additively.
Constraints: only .js/.jsx (no TypeScript, Principle V override); no backend/
model/API changes; no new routes; zero new runtime dependencies; search
case-insensitive substring matching (S1); debounce 200-300ms (S2); filters
compose as AND (S3); designed empty states + clear-all (S4/S6); URL query-param
persistence via useSearchParams, no localStorage/backend (S5); progressive
disclosure on mobile (S7); read-only no mutation (S8); responsive filter
layout (S9); accessibility labels/keyboard/aria-live (S10); dark green-accent
tokens matching HistoryFilters/Dashboard; global search "(if required)" as a
deferred option. Plan MUST cover: Overall Approach; Ordered Task List (Tn with
ID, title, exact files, implementation, acceptance criteria, dependencies);
File Creation Order; State Management Plan; Testing & Verification Plan;
Definition of Done; Out of Scope Reminder; Constitution Check and Complexity
Tracking. Write to specs/008-search-filtering/plan.md, then create a PHR
(stage: plan).
