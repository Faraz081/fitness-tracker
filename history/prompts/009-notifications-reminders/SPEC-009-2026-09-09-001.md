## Prompt

/sp.specify

Create a detailed functional specification for the Notifications & Reminders system of the FitTrack application based on the constitution already defined.

### Feature: Notifications & Reminders (6.1)

#### 1. Overview
A complete notification system that keeps users informed about workout completions, goal progress, and important reminders, while giving them full control over what they receive.

#### 2. Notifications Page
- Dedicated page accessible from the left sidebar.
- Shows a chronological list of all notifications.
- Each notification displays:
  - Title / message
  - Timestamp
  - Type (Workout, Goal, Meal, Reminder, etc.)
  - Read / Unread visual state
- Unread notifications must be visually distinct.
- User can mark individual notifications as read or mark all as read.
- Empty state when there are no notifications.

#### 3. Notification Types

**Event-based Notifications**
- Workout completion notification (triggered when a workout is finished)
- Goal progress notification (triggered when significant progress is made toward a goal)
- Goal completed notification (triggered when a goal is fully achieved)

**Reminder Notifications**
- Workout reminder (remind user about a planned or habitual workout)
- Meal reminder (remind user to log a meal)
- Goal reminder (remind user about an active goal)

#### 4. Read / Unread State
- Every notification has a read/unread status.
- Status must be persisted.
- Unread count can be shown on the sidebar or notification icon (if applicable).
- User can mark as read individually or mark all as read.

#### 5. Notification Settings
- Dedicated settings section (or page) where users can enable/disable each notification type:
  - Workout completion
  - Goal progress
  - Goal completed
  - Workout reminder
  - Meal reminder
  - Goal reminder
- Settings must be saved and respected by the system.
- Default state: all important notifications enabled.

#### 6. Behavior Rules
- Do not send duplicate notifications for the same event.
- Respect user settings — if a type is disabled, never send it.
- Notifications should be created at the correct moment (on workout complete, on goal progress, etc.).
- Reminders should only be sent when relevant (e.g., user has an active goal or typical workout time).

#### 7. UI Rules (Strict)
- Notifications page must match the Dashboard design system exactly:
  - Same left sidebar
  - Same dark theme and green accents
  - Same card style and tight content layout (minimal side gaps)
- Unread vs read states must be clear.
- Settings UI must be simple and consistent with the rest of the app.
- Empty states must be friendly and helpful.

#### 8. Acceptance Criteria
- [ ] Notifications page exists and is accessible from the sidebar
- [ ] Workout completion, goal progress, and goal completed notifications work
- [ ] Workout, meal, and goal reminders work
- [ ] Read/unread state is correctly managed
- [ ] Notification settings allow enabling/disabling each type
- [ ] UI is visually consistent with the Dashboard
- [ ] Empty states are handled properly
- [ ] No duplicate or unwanted notifications are sent

   - P1: View & manage notifications in an inbox (page, list, read/unread, badge,
     empty state, persistence) — the highest-value standalone slice.
   - P2: Event-based notifications (workout completion, goal progress, goal
     completed) + per-type settings with instant respect.

     no same-day duplication.

3. **26 functional requirements (FR-001 → FR-026)** covering the page list and
   layout, all six types, relevance guards, read/unread + persistence, dedup,

   read state, unique per event), Notification Settings (per-type on/off, default
