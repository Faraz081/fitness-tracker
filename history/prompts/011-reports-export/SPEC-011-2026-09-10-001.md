## Prompt

/sp.specify for the Day 8.1 Reports & Export module (governed by constitution
v3.8.0 Day 8.1). Must produce a precise, implementation-ready specification
covering: (1) User Stories for each capability — viewing the Fitness Report
(overview dashboard), the three detailed reports (Workout, Nutrition, Progress),
changing date range, exporting CSV, and exporting PDF; (2) Detailed Functional
Specification — screen/component-level behavior for the four reports, exact
metrics/tables/charts per report, date-range selector behavior (presets + custom,
default value, effect on data), exact CSV columns/data per report type, and PDF
structure/content/layout (title, date range, summary cards, tables, charts as
images, branding, timestamp); (3) UI/UX — reports-section layout and navigation,
placement of date range + export buttons, loading/empty/error states for reports
and both export actions, responsive desktop vs mobile, accessibility; (4) Data &
Calculation Rules — formulas for total volume, consistency score, calorie
adherence, weight change, strength progress, plus data sources, aggregation
rules, and timezone handling; (5) API/Backend Expectations (high-level) — data
contracts/endpoints needed to support reports and exports, and performance
expectations for fetching and file generation; (6) Acceptance Criteria —
testable criteria for every major feature including no-data, very-large-range,
and failed-export edge cases; (7) Edge Cases & Error Handling — no data in range,
partial data, export failures/timeouts, very large ranges, missing goals or
incomplete profile. Output must be structured with clear headings for direct use
by developers and designers, concrete over vague.
