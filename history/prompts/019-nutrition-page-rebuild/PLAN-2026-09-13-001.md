## Prompt

/sp.plan

Create a detailed implementation plan for completely rebuilding the Nutrition page from scratch based on the constitution and specification already defined.

### Goal
Fully delete the current broken Nutrition page implementation, then rebuild a clean, minimal AI Food Search page that matches the required structure exactly — with live Gemini search, meal tabs, persisted meal logs, and no extra features.

### Phase 1: Complete Deletion
1. Identify the current Nutrition page file(s), components, hooks, and related state created specifically for it.
2. Completely delete/remove the existing Nutrition page implementation.
3. Remove related broken components and page-specific state.
4. Confirm the old implementation is fully gone before starting any new build.
5. Do not patch or reuse the broken page.

### Phase 2: Page Shell
1. Create a clean new Nutrition page.
2. Build the required header:
   - Fork/utensil icon
   - Title: "AI Food Search"
3. Keep the page minimal and free of unlisted extra sections.

### Phase 3: Search UI
1. Add a single search input with placeholder like "banana".
2. Add a "Search" button.
3. Add helper text:
   "Supports natural language — try 'large chicken breast' or '100g of oats with milk'"
4. Wire search submission to the backend Gemini analysis endpoint.
5. Ensure every search hits Gemini live.
6. Ensure the Gemini API key remains backend-only.

### Phase 4: Search Result Section
1. After a successful search, show a section labeled:
   "1 RESULT — CLICK TO ADD"
2. Add a "Clear" action on the right.
3. Render the result row with:
   - Food name
   - Serving size (e.g. "per 118g")
   - CAL / P / C / F badges in distinct colors
   - "+" icon
4. Do not use static/hardcoded nutrition data as the source of truth.
5. Handle loading and failure states simply.

### Phase 5: Meal Tabs & Empty States
1. Add four tabs only:
   - Breakfast
   - Lunch
   - Dinner
   - Snacks
2. Add the required icons:
   - Breakfast: coffee cup
   - Lunch: sun
   - Dinner: moon
   - Snacks: clock
3. For each empty meal section, show:
   - Plate/utensils icon
   - "No food logged for [Meal Name]"
   - "Use AI search above to find and add foods."

### Phase 6: Add Food + Persistence
1. When the user clicks "+", add the food to the selected/relevant meal flow.
2. Save the food entry to the real backend/database.
3. Include authenticated user ID, food name, meal type, and nutrition values.
4. Show the added food under the correct meal section with its logged macros.
5. Ensure the entry persists and is not local/session-only.
6. Ensure one user cannot see another user's food logs.

### Phase 7: Strict Scope Enforcement
1. Do not add a date picker.
2. Do not add a separate macro summary bar.
3. Do not add extra filters.
4. Do not add duplicate search bars.
5. Do not add extra sidebar widgets on this page.
6. Keep only the required structure.

### Phase 8: Verification
1. Confirm old Nutrition implementation is fully deleted.
2. Confirm the new page matches the required structure exactly.
3. Test live Gemini search and result rendering.
4. Test Clear.
5. Test adding food under Breakfast / Lunch / Dinner / Snacks.
6. Test empty states.
7. Test persistence after refresh.
8. Confirm no unlisted features were introduced.

### Recommended Order
1. Delete old Nutrition page completely
2. Build clean page shell + header
3. Build search bar + Gemini live lookup
4. Build result section
5. Build meal tabs + empty states
6. Build add/persist flow
7. Enforce strict scope
8. Final verification

### Definition of Done
- Old Nutrition page is fully deleted
- New page matches the required structure exactly
- Live Gemini search works
- Foods can be added and persisted under meal tabs
- Empty states are correct
- No extra unlisted features exist
- Page is clean, minimal, and functional
