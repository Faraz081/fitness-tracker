## Prompt

/sp.specify

Create a detailed functional specification for completely rebuilding the Nutrition page from scratch based on the constitution already defined.

### Feature: Nutrition Page Rebuild (AI Food Search)

#### 1. Overview
Completely remove the current broken Nutrition page implementation and rebuild a clean, minimal AI Food Search page that matches the required structure exactly. Do not patch the old page. Do not add extra features.

#### 2. Deletion Requirement
Before building anything new:
- Completely delete/remove the existing Nutrition page
- Remove all current components, related state, and files created specifically for it
- Do not reuse or partially edit the broken implementation
- Confirm deletion is complete before starting the rebuild

#### 3. Required Page Structure

**A. Header**
- Fork/utensil icon
- Title text: "AI Food Search"

**B. Search Bar**
- Single search input
- Placeholder example: "banana"
- A "Search" button next to the input
- Helper text below:
  "Supports natural language — try 'large chicken breast' or '100g of oats with milk'"

**C. Search Result**
- Appears after a successful search
- Section label: "1 RESULT — CLICK TO ADD"
- "Clear" link on the right side of the section
- Result row must show:
  - Food name
  - Serving size (example: "per 118g")
  - Four colored badges:
    - CAL (kcal)
    - P (protein g)
    - C (carbs g)
    - F (fat g)
  - A "+" icon at the end of the row to add the food
- Nutrition data must come from a live Gemini API call
- No static/hardcoded nutrition data is allowed as the source of truth

**D. Meal Tabs**
- Four tabs only:
  - Breakfast
  - Lunch
  - Dinner
  - Snacks
- Each tab has its own icon:
  - Breakfast: coffee cup
  - Lunch: sun
  - Dinner: moon
  - Snacks: clock

**E. Meal Section**
- Empty state:
  - Plate/utensils icon
  - Text: "No food logged for [Meal Name]"
  - Hint: "Use AI search above to find and add foods."
- When food is added:
  - Display the food under the selected meal
  - Show its logged macros
  - Persist the entry to the backend/database
  - Do not store it as local-only/session-only state

#### 4. Behavior Rules
- User types a food name and clicks Search
- Backend calls Gemini in real time
- Result appears in the required result section
- User clicks "+" to add the food to the currently relevant/selected meal flow
- Added food appears under the correct meal tab section
- Clear removes the current search result
- All saved foods must be scoped to the authenticated user

#### 5. Strict Scope Limits
Do NOT add:
- Date picker
- Separate macro summary bar
- Extra filters
- Duplicate search bars
- Extra sidebar widgets on this page
- Any feature not explicitly listed above

The goal is a clean, minimal, working version only.

#### 6. Technical Rules
- Gemini API key must remain backend-only
- Every search must hit Gemini live
- Saved foods must persist in the real backend/database
- Prefer a simple and maintainable implementation
- Confirm old page deletion before rebuilding

#### 7. Acceptance Criteria
- [ ] Old Nutrition page implementation is fully deleted
- [ ] New page has the exact required header
- [ ] New page has the exact required search bar and helper text
- [ ] Live Gemini search returns a result in the required format
- [ ] Result row includes food name, serving size, CAL/P/C/F badges, and "+"
- [ ] Clear works
- [ ] Meal tabs exist for Breakfast, Lunch, Dinner, Snacks with icons
- [ ] Empty meal state matches the required text/icon
- [ ] Added foods persist and appear under the selected meal
- [ ] No unlisted extra features were added
- [ ] Page remains clean, minimal, and functional
