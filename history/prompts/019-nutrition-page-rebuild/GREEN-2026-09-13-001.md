## Prompt

/sp.implement

Implement the complete Nutrition page rebuild according to the constitution, specification, plan, and tasks already defined.

### Implementation Instructions

Follow this order strictly:

1. **Complete Deletion**
   - Identify the current Nutrition page files, components, hooks, and page-specific state.
   - Completely delete the existing Nutrition page implementation.
   - Remove all related broken components and state created specifically for it.
   - Confirm the old implementation is fully gone.
   - Do not patch or reuse the broken page.
   - Do not begin the new build until deletion is confirmed complete.

2. **Clean Page Shell**
   - Create a new clean Nutrition page.
   - Add the required header with a fork/utensil icon.
   - Add the title: “AI Food Search”.
   - Keep the page minimal and free of unlisted sections.

3. **Search UI**
   - Add a single search input with placeholder like “banana”.
   - Add a “Search” button.
   - Add helper text:
     “Supports natural language — try 'large chicken breast' or '100g of oats with milk'”
   - Wire search submission to the backend Gemini analysis endpoint.
   - Ensure every search hits Gemini live.
   - Keep the Gemini API key backend-only.

4. **Search Result Section**
   - After a successful search, show:
     “1 RESULT — CLICK TO ADD”
   - Add a “Clear” action on the right.
   - Render the result row with:
     - Food name
     - Serving size (e.g. “per 118g”)
     - CAL / P / C / F badges in distinct colors
     - “+” icon
   - Use live Gemini data only.
   - Do not use static/hardcoded nutrition data as the source of truth.
   - Handle simple loading and failure states.

5. **Meal Tabs & Empty States**
   - Add exactly four tabs:
     - Breakfast
     - Lunch
     - Dinner
     - Snacks
   - Add the required icons:
     - Breakfast: coffee cup
     - Lunch: sun
     - Dinner: moon
     - Snacks: clock
   - For empty meals, show:
     - Plate/utensils icon
     - “No food logged for [Meal Name]”
     - “Use AI search above to find and add foods.”

6. **Add Food + Persistence**
   - When the user clicks “+”, add the food into the selected/relevant meal flow.
   - Save the entry to the real backend/database.
   - Store authenticated user ID, food name, meal type, and nutrition values.
   - Display the added food under the correct meal section with its macros.
   - Ensure persistence is not local/session-only.
   - Enforce authenticated user scoping so users cannot access each other’s logs.

7. **Strict Scope Enforcement**
   - Do not add a date picker.
   - Do not add a separate macro summary bar.
   - Do not add extra filters.
   - Do not add duplicate search bars.
   - Do not add extra sidebar widgets on this page.
   - Build only the required structure.

8. **Final Verification**
   - Confirm the old Nutrition implementation is fully deleted.
   - Confirm the new page matches the required structure exactly.
   - Test live Gemini search and result rendering.
   - Test Clear.
   - Test adding food under Breakfast / Lunch / Dinner / Snacks.
   - Test empty states.
   - Test persistence after refresh.
   - Confirm no unlisted features were added.

### Rules
- Delete first. Build second.
- Match the required structure exactly.
- Keep the page clean and minimal.
- Every search must hit Gemini live through the backend.
- Saved foods must persist in the real database.
- No static nutrition source of truth.
- No scope creep.
- Follow all acceptance criteria from the specification.

Start from step 1 and proceed sequentially.
